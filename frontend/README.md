# SubForge 内置页面

原生 HTML、CSS 和 JavaScript 单页，没有前端框架、构建步骤或 npm 运行依赖。订阅配置、转换选项、三个可选脚本和生成结果在同一页面纵向排列。浅色模式使用白色背景和中性灰配色，暗色模式跟随系统偏好自动切换。页头显示当前程序版本和仓库地址，两者由服务端在渲染首页时从 Cargo 元数据注入，不需要前端请求额外接口。

浏览器调用 `POST /api/v1/subscriptions`，把订阅参数、转换选项和脚本原文交给后端保存到 SQLite。后端返回短订阅链接；页面只负责输入、请求、展示、复制和下载，不再压缩脚本或编码参数，不加载第三方 CDN 库。配置文件名称可选，留空时使用 `sub-forge`；下载时从响应的 `Content-Disposition` 读取最终文件名，中文名称也能正确保存。

规则模板区域提供“ACL4SSR 预设”和“自定义链接”两种模式。默认使用推荐的标准版；18 个官方在线模板按标准版、完整版和精简版分组，展开列表时，每个选项同时展示名称和可换行的完整 URL；支持方向键、Home / End、Enter 和 Esc 操作。选择后显示用途说明，可通过“查看模板”打开原始文件。自定义模式只显示 INI 链接输入框；来回切换会分别保留当前模板和自定义地址，仅当前模式的配置参与校验和生成。预设列表内置于页面，浏览时不请求 GitHub API；实际使用订阅时由后端获取规则模板。

页面顶部以“新建订阅”和“更新订阅”两个标签切换操作，样式与规则模板选择一致。新建始终生成独立链接；更新需要填写本站短链接和管理 token，点击“载入配置”回填全部字段、规则模板和脚本，再保存到原链接。切换标签保留表单内容并清除编辑目标；切回新建可将当前配置另存为独立链接，切回更新必须重新载入。载入和更新都由后端校验，浏览器不直接请求粘贴的订阅地址。修改已有链接输入会退出当前编辑目标，重新载入后才能更新该链接。

## 运行与部署

前端编译进 Rust 程序，与 API 共用一个端口。没有独立前端容器或 Nginx 配置。仓库根目录运行：

```bash
cargo run --locked -p sub-forge
```

先按根目录 `.env.example` 配置环境变量，默认打开 `http://127.0.0.1:8080/`。修改页面文件后重新编译，程序运行时不读取这些文件。构建 Docker 镜像时也会自动嵌入资源。

页面自动调用当前站点的 `/api/v1/subscriptions`，无需填写后端地址或设置 CORS。“下载配置”通过同源 API 和生成记录的 ID 请求；复制给客户端的公开 URL 由 `SUB_FORGE_PUBLIC_BASE_URL` 决定。

服务端设置 `SUB_FORGE_ACCESS_TOKEN` 时，页面渲染“管理 token”输入框并在生成、载入和更新请求的 Bearer 头中发送；未设置时服务端在 HTML 中写入公开部署标记，页面隐藏并禁用该字段，因此公开服务不会出现无意义的 token 输入框。该字段是部署管理凭据而不是登录密码：`body` 和输入框带有 `data-1p-ignore`、`data-op-ignore`、`data-bwignore`、`data-lpignore` 标记，避免 1Password 等密码管理器把表单提交识别为登录并提示保存密码。下载、客户端访问和转换器回调无需 token，链接中也不会包含它。持有短链接即可读取对应内容，请妥善保管。

需要 HTTPS 时由外部反向代理统一转发整个站点到程序端口。部署到路径前缀时，代理应去除前缀后转发，并将前缀根路径重定向到带尾部 `/` 的地址，保证页面资源和 API 相对路径正确。

网页 CSP 只允许内置脚本、样式和同源 API，不加载 CDN，也不在浏览器中执行用户脚本。普通页面访问无需鉴权，业务请求仍须通过后端验证。

## 参数与脚本

请求字段及默认值见[核心 README](../crates/sub-forge/README.md#生成订阅链接)。前端提交完整选项、文件名称和原始脚本文本，后端负责 URL、选项、文件名、长度和脚本语法校验。文件名只接受不含扩展名的单段名称，下载扩展名由服务添加。脚本保留注释和排版，不压缩、不执行；实际执行发生在使用订阅时。

三个脚本合计最多 64 KiB，请求 JSON 最多 512 KiB，输入 URL 最多 2048 字节。订阅及回调 ID 固定为 32 字符，与脚本长度无关。

生成、载入和更新请求超时为 30 秒，下载超时为 70 秒。修改输入会取消当前请求并清除旧结果，迟到的响应不能覆盖新配置。浏览器取消请求不保证撤销已提交的保存；重新新建会得到独立链接；更新同一 ID 会替换该订阅配置。

页面输入和结果只保存在内存，不使用 localStorage，刷新页面后清空。已提交的参数和脚本会持久保存于后端，已有订阅链接不受页面刷新影响。旧编码链接需要在新前端重新生成。

## 代码组织

前端采用浏览器原生 ES Modules，仍然无需构建。`app.js` 管理页面状态、表单数据、复制和下载；`api.js` 统一处理请求、超时、取消和错误；`rules-picker.js` 封装规则模式切换、预设选择和键盘交互。`http/frontend.rs` 将这些文件嵌入同一个可执行程序，通过 HTTP(S) 访问。

## 验证

```bash
for file in frontend/*.js; do node --check "$file"; done
```

CI 检查 JavaScript 语法，功能验证使用实际浏览器交互和隔离的 HTTP 调用。
